# 浏览器组件测试反馈修复设计

## 背景

浏览器执行配置页的“测试浏览器组件”按钮会正确请求后端，生产日志也显示接口返回 `200`。但成功或失败信息统一渲染在整页末尾，用户在页面顶部点击后无法看到；按钮本身也没有进行中状态，因此看起来像没有响应。

## 目标

- 点击后立即在按钮附近显示明确的进行中反馈。
- 请求完成后在“服务状态”区域原地显示成功或失败结果。
- 测试期间禁用按钮，避免重复提交。
- 明确当前测试是 Browser Worker 健康检查，不暗示已经执行真实页面导航。

## 交互设计

页面新增独立的组件测试状态，不与保存配置的提示混用：

1. 点击按钮时清除上一次测试结果，按钮变为“测试中…”，并暂时禁用。
2. 成功响应后，在按钮所在操作行下方展示接口消息；无论 `ok` 为 `true` 还是 `false`，都按照实际结果分别使用状态提示或错误提示。
3. 请求失败时，在原位置展示“浏览器组件测试失败”。
4. 测试结束后恢复按钮可用状态。

## 视觉约束

- 模式：Extension。
- 视觉变化强度：1/10；动效强度：1/10；信息密度保持现状；品牌一致性：10/10。
- 复用 `configuration-save-notice`、`configuration-inline-error` 和现有按钮样式。
- 不新增颜色、阴影、边框、卡片或动画。
- 状态提示使用 `role="status"`，失败提示使用 `role="alert"`。

## 技术范围

- 修改 `src/web/pages/browser-automation-page.tsx`，增加测试状态和原地反馈。
- 修改 `src/web/pages/browser-automation-page.test.tsx`，覆盖进行中、成功、业务失败和请求失败状态。
- 不修改后端接口、配置结构、路由或持久化数据。

## 验收标准

- 用户点击后无需滚动即可看到状态变化。
- 测试期间按钮不可重复点击。
- `ok: true` 显示成功提示；`ok: false` 和网络异常显示错误提示。
- 保存配置的提示与组件测试结果互不覆盖。
