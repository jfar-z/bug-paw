# ADR-0002：在单服务实例内保证多客户端 Session 同步

- 状态：已接受
- 日期：2026-08-07

## 背景

同一用户可能同时通过桌面浏览器、移动浏览器和 PWA 查看同一个 Session。当前 SSE 路径存在 Runtime 重复解析、连接与订阅对象不一致、重连恢复能力不足和慢客户端内存无上限等风险。系统没有部署多副本的需求，但必须清楚区分“多个客户端”与“多个服务实例”。

## 决策

BugPaw 对连接到同一个服务实例的多个客户端提供 Session 级同步保证：

- 每个 Session 的事件序号单调递增；
- 服务端广播 Turn 受理、文本与思考增量、工具状态、运行状态、模型变化和终止事件；
- 客户端按事件标识幂等应用；
- 重连优先使用 `Last-Event-ID` 重放有界事件日志，缺口超出窗口时返回完整 Session Projection；
- 中途加入的客户端先取得 Projection，再订阅后续事件；
- 每个客户端具有有界发送队列，溢出后中止增量重放并要求快照恢复；
- 同一 Session 同时最多运行一个 Turn；提交、终止和结束状态在全部已连接客户端间同步；
- 草稿文本属于设备本地状态，不参与同步。

服务启动时对数据目录获取独占实例锁。无法获得锁时拒绝启动，以免两个进程分别维护 Runtime 和事件序号并向客户端产生分叉。当前不支持负载均衡后的多服务副本；若未来需要横向扩容，必须新增共享事件总线、分布式 Session 所有权与分布式锁，并另立 ADR。

## 结果

桌面端、移动端和 PWA 可以可靠观察同一 Agent 输出，并在临时断网后恢复。事件日志、连接队列和 Projection 都必须有明确上限，不能以无限内存换取同步能力。

该保证不涵盖连接到不同 BugPaw 服务实例的客户端。单实例锁会让误配置尽早失败，而不是静默产生不一致。

## 被否决的方案

- 每个浏览器独立轮询：延迟高，无法可靠恢复流式增量和终止状态。
- 只广播文本 Delta：工具、模型、终止和运行状态仍会在多端分叉。
- 当前阶段引入 Redis 等共享总线：没有多副本需求，运维成本大于收益。
