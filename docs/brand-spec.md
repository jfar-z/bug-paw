# BugPaw 视觉风格标准

## 1. 适用范围

本文档是 BugPaw Web 应用的唯一现行视觉标准，适用于登录、初始化、聊天、工作台、配置、知识库及后续新增页面。历史设计稿与探索记录不属于现行规范；如与本文冲突，以本文为准。

本次生产迁移采用 **Redesign · Overhaul**：更新品牌资产与视觉语言，但保持路由、信息架构、文案含义、表单字段、数据流、键盘行为、测试选择器和业务交互不变。

## 2. 品牌定位

BugPaw 是面向开发者和个人部署用户的本地 AI Agent 工作台。品牌人格来自真实猫咪 BUG：安静、聪明、可靠，带一点克制的像素趣味。

- 不使用泛化机器人、AI 气泡、霓虹赛博或大面积渐变表达智能感。
- 日常工作区以清晰、稳定、高信息密度为第一优先级。
- 猫咪和像素语言只承担品牌识别、空状态和轻量反馈，不覆盖业务内容。

## 3. 设计读法

| 维度 | 标准 |
| --- | --- |
| 产物 | 桌面优先、兼容移动端与 PWA 的操作型 Web 工作台 |
| 用户 | 自托管用户、开发者和需要长时间阅读配置与对话的用户 |
| 视觉语言 | 克制的开发者工具界面 + BUG 虎斑像素品牌层 |
| 视觉变化度 | 5/10；结构稳定，品牌主题允许少量硬边像素表达 |
| 动效强度 | 3/10；仅用于状态反馈、切换和轻量进入效果 |
| 信息密度 | 8/10；保持列表、配置和对话的扫描效率 |
| 资产依赖 | 7/10；真实 BUG 资产是主要品牌识别来源 |
| 品牌一致性 | 10/10；只能使用本清单中的正式资产与色彩角色 |

### 5.5 语义约束

- 猫眼绿只用于成功、在线、焦点和品牌重点，不覆盖所有交互色。
- 肉垫粉不作为危险色或主按钮底色。
- 危险状态在三套主题中都必须保持独立红色语义。
- 文本、边框和交互状态必须满足 WCAG AA；不能只依赖颜色表达状态。

## 6. 字体与可读性

- 正文与界面：`Manrope Variable`，回退到无衬线系统字体。
- 代码、路径、时间、状态标签和短元数据：`JetBrains Mono`。
- 页面正文基准字号为 `14px`；对话、表单说明与设置描述建议 `13–15px`。
- 关键交互文字和持续阅读文字不得小于 `11px`；`10px` 只允许用于非关键、极短的辅助标记。
- 禁止使用 `7px`、`8px`、`9px` 的可见文字。
- 正文行高使用 `1.55–1.7`，紧凑标签使用 `1.2–1.4`。
- 像素字体或像素化效果不用于正文、表单说明、对话和长文本。

## 7. 间距、形状与层级

- 使用 4px 基础网格，常用间距为 `4 / 8 / 12 / 16 / 20 / 24 / 32px`。
- 桌面操作控件高度不低于 `36px`；图标按钮建议 `40px`；移动端主要触控区域不低于 `44px`。
- 深色/浅色主题：输入框与按钮 `7–10px` 圆角，主要面板 `9–12px` 圆角。
- BUG 主题：控件 `2–4px`、面板 `4–6px` 圆角，用 2px 实线边框和 `3–4px` 无模糊硬阴影形成像素层次。
- 日常列表以分隔线、留白和背景层级分组，避免把每段内容都卡片化。
- 同一层级最多使用一种阴影；工作区不使用大面积发光、玻璃拟态或装饰渐变。

## 8. 组件规则

### 产品标识

- 完整模式：深棕肉垫猫头 + `BugPaw` + 可选短副标题。
- 紧凑模式：只显示深棕肉垫猫头，不使用 π 字符或旧 Pi Agent 标识。
- 猫头在导航中建议显示为 `32–40px`，使用 `image-rendering: auto`，不得压缩变形。

### 导航与工作区

- 保持现有一级/二级导航、路由、标签和移动端抽屉行为。
- 选中态使用背景、文字和边缘提示的组合；BUG 主题可使用肉垫粉作窄边提示。
- 稳定信息密度，品牌装饰不能挤压会话、配置和文件列表。

### 表单与按钮

- 主按钮每个任务区域只保留一个明确层级。
- 必须覆盖 hover、focus-visible、active、disabled、loading 和 error 状态。
- 不改变字段名、顺序、自动填充属性、验证规则或提交行为。

### 插画

- 登录/初始化可使用横幅插画作为唯一大图。
- 配置概览最多使用一张主吉祥物图。
- 知识库、资源页仅在空状态使用睡眠图。
- 同一屏最多出现一张大尺寸 BUG 插画；列表行和高密度表格不放猫咪装饰。

## 9. 动效与无障碍

- 默认动效时长 `140–180ms`，仅反馈悬停、按下、展开、主题切换和状态变化。
- BUG 主题按钮按下可用 `translate(2px, 2px)` 配合硬阴影缩短，模拟像素按钮。
- 支持 `prefers-reduced-motion: reduce`，移除非必要位移和过渡。
- 所有图标按钮必须有可访问名称；焦点环使用 Eye Green，并与背景保持对比。
- 不使用 `window.alert`、`window.confirm`、`window.prompt`。

## 10. 响应式规则

- `≥ 1100px`：保留一级轨道、二级导航和主内容三段式结构。
- `760–1099px`：允许收窄或折叠次级信息，但保持主要任务和主题入口可达。
- `< 760px`：导航进入应用内抽屉；主要触控区域不低于 44px；登录品牌插画降级为紧凑品牌区。
- 任何宽度都不得出现横向页面滚动、不可见主操作或被裁切的错误提示。

## 11. 资产与视觉变更检查

每次提交视觉变更前检查：

1. 新资产是否在正式清单中，并且有唯一明确用途。
2. 是否遗留生成源图、候选稿、同内容重复副本或不再引用的旧版本。
3. 三套主题的正文、次级文字、边框、焦点、危险色是否仍清晰。
4. 是否出现小于 10px 的文字，或小于 11px 的关键文字。
5. 是否保持路由、表单、数据流、测试选择器和键盘行为。
6. favicon、PWA 图标和页面猫头是否各自使用正确资产。
7. 登录、配置与空状态插画是否遵守“一屏一张大图”。
