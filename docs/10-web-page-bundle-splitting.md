# Web 页面分包与 Bundle 预算规范

本文约束 BugPaw Web 页面、页面样式、共享组件样式、Bundle 预算与 PWA 预缓存的新增和修改方式。目标是让首屏只承担应用壳成本，让独立页面按需加载，同时通过可审查的页面级预算阻止体积持续回流到公共入口。

## 1. 适用范围

出现以下任一变更时必须遵守本文：

- 新增、拆分、合并或重命名 `src/web/pages/` 下的页面入口。
- 调整 `src/web/app.tsx` 中的页面加载方式。
- 新增页面专属 CSS、跨页面领域 CSS 或重型组件 CSS。
- 修改 `config/bundle-budget.json`、`scripts/check-bundle.mjs` 或 `scripts/build-pwa.mjs`。
- 引入可能显著增加 JavaScript 或 CSS 体积的页面依赖。

## 2. 分包边界

### 2.1 页面入口

独立页面必须通过 `React.lazy()` 动态导入，页面实现不得静态导入到应用入口。Vite 生产 Manifest 中，该页面应表现为 `src/web/pages/*.tsx` 动态入口。

只有首屏渲染前必需的应用壳、主题令牌、基础布局、字体和全局重置可以进入 `src/web/main.tsx` 及其入口 CSS。页面卡片、表单、列表、编辑器、工作台和响应式细节不得放回全局入口样式。

### 2.2 页面与领域样式

- 单页面使用的样式放入对应页面 CSS，并由该页面入口直接导入。
- 多个相关页面共同使用的样式放入领域 CSS，由每个需要它的懒加载页面显式导入。
- 只有某个懒加载组件使用的重型样式，应由该组件导入。例如 Markdown、代码高亮、公式或编辑器样式不应随应用壳加载。
- 不得为了减少 import 行数，把页面样式重新汇总进 `styles.css`、`main.tsx` 或其他首屏静态依赖。
- 样式拆分以加载边界和领域归属为准，不要求每个页面机械地拥有一个 CSS 文件；共享领域 Chunk 可以被多个页面复用。

修改样式边界时，应同步维护 `src/web/page-styles.test.ts` 中的代表选择器和页面导入关系，防止页面规则重新进入首屏 CSS。

## 3. Bundle 预算

`config/bundle-budget.json` 是 Bundle 预算的唯一真实来源。预算分为四层：

| 预算 | 约束对象 | 目的 |
| --- | --- | --- |
| `entryJsGzipBytes` | JavaScript 入口 | 控制首屏脚本成本。 |
| `lazyChunkGzipBytes` | 单个懒加载 JavaScript Chunk | 防止单页脚本无限增长。 |
| `css.entryGzipBytes` | 首屏静态 CSS 依赖 | 保持应用壳轻量。 |
| `css.totalGzipBytes` | 全部 CSS Chunk 去重后的总量 | 控制全站样式规模。 |
| `css.routes` | 各动态页面相对首屏新增的 CSS | 按页面约束独立加载成本。 |

所有 `src/web/pages/` 动态入口必须在 `css.routes` 登记，键名必须与 Vite Manifest 的源码入口一致。缺少登记本身就是门禁失败，不能依赖全站总预算代替页面预算。

页面 CSS 预算按“该页面静态 CSS 依赖减去首屏 CSS 依赖”计算。共享领域 CSS 会计入每个使用它的页面预算，但在全站总量中只计一次。这种计算同时反映用户首次进入页面的真实增量和全站发布成本。

### 3.1 预算设置原则

- 新页面先完成真实内容和样式分包，再以生产构建的 gzip 结果设定预算。
- 预算应取略高于稳定测量值、便于审查的整数档位；保留小幅正常波动空间，但不得为未实现的未来功能预留大额容量。
- 页面接近预算时，优先删除重复规则、下沉组件样式或拆分加载边界，不得直接把样式移回入口 CSS。
- 调高任一预算必须在变更说明中给出增长来源、测量结果和无法继续拆分的理由。禁止仅为通过 CI 而整体放宽预算。
- 页面删除或重命名时必须同步删除或迁移预算项；预算指向不存在的 Manifest 入口同样属于错误。

## 4. PWA 预缓存

`scripts/build-pwa.mjs` 必须从 Vite Manifest 收集应用入口、全部动态页面及其静态依赖，不维护手写页面白名单。新增页面正常进入 Manifest 后，其 JavaScript、CSS 和共享依赖应自动进入 Service Worker 预缓存。

修改页面入口结构、Manifest 遍历或 CSS 加载边界时，必须同步验证：

- 至少存在一个动态页面入口，否则 PWA 构建应失败。
- 页面 JavaScript、页面 CSS 和递归静态依赖均写入 `sw.js`。
- 预缓存资源去重并保持稳定排序。
- 不把运行时 API、用户数据或带凭据 URL 纳入静态预缓存。

## 5. 测试与验证

涉及分包的变更至少应覆盖以下自动化检查：

- `src/web/page-styles.test.ts`：页面样式不在首屏 CSS，且由正确入口或组件加载。
- `scripts/check-bundle.test.ts`：首屏、总量、页面预算、缺失预算和异常 Manifest 的门禁行为。
- `scripts/build-pwa.test.ts`：全部动态页面及其 CSS、共享依赖进入预缓存。
- 现有主题测试：新增 CSS 继续遵循主题令牌和禁止硬编码颜色等约束。

最终必须在项目规定的 Node Docker 环境中执行 `npm run verify`。评审时应记录门禁输出中的首屏 CSS、CSS 总量和受影响页面的 gzip 实测值；只运行开发服务器不能证明生产分包正确。

## 6. 新增页面检查清单

1. 在 `src/web/app.tsx` 使用 `React.lazy()` 动态导入页面。
2. 将页面专属规则放入页面或领域 CSS，并从懒加载边界导入。
3. 在 `config/bundle-budget.json` 为页面登记独立 CSS gzip 预算。
4. 更新样式边界、Bundle 门禁和 PWA 预缓存相关测试。
5. 执行生产构建，确认 Vite Manifest 中存在动态页面及预期 CSS Chunk。
6. 执行 `npm run verify`，记录并审查首屏、总量和页面级预算结果。

## 7. 禁止做法

- 静态导入本可独立加载的页面，只为绕过页面预算登记。
- 把页面专属 CSS 放进全局入口，导致所有用户提前下载。
- 使用空页面、测试桩或临时删除样式得到虚假的低基线。
- 删除门禁测试、跳过生产构建或无理由扩大预算。
- 为 PWA 新页面维护手写资源列表，使 Manifest 与缓存范围脱节。
