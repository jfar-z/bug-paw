# Web 页面分包与 Bundle 预算规范

本文约束 BugPaw Web 页面、页面样式、共享组件样式、Bundle 预算与 PWA 预缓存的新增和修改方式。目标是让首屏只承担应用壳成本，让独立页面按需加载，同时通过可审查的页面级预算阻止体积持续回流到公共入口。

## 1. 适用范围

出现以下任一变更时必须遵守本文：

- 新增、拆分、合并或重命名 `src/web/pages/` 下的页面入口。
- 调整 `src/web/app.tsx` 中的页面加载方式。
- 新增页面专属 CSS、跨页面领域 CSS 或重型组件 CSS。
- 修改 `config/bundle-budget.json`、`scripts/check-bundle.mjs` 或 `scripts/build-pwa.mjs`。
- 引入可能显著增加 JavaScript 或 CSS 体积的页面依赖。

## 2. 分包边界

### 2.1 页面入口

独立页面必须通过 `React.lazy()` 动态导入，页面实现不得静态导入到应用入口。Vite 生产 Manifest 中，该页面应表现为 `src/web/pages/*.tsx` 动态入口。

只有首屏渲染前必需的应用壳、主题令牌、基础布局、字体和全局重置可以进入 `src/web/main.tsx` 及其入口 CSS。页面卡片、表单、列表、编辑器、工作台和响应式细节不得放回全局入口样式。

### 2.2 页面与领域样式

- 单页面使用的样式放入对应页面 CSS，并由该页面入口直接导入。
- 多个相关页面共同使用的样式放入领域 CSS，由每个需要它的懒加载页面显式导入。
- 只有某个懒加载组件使用的重型样式，应由该组件导入。例如 Markdown、代码高亮、公式或编辑器样式不应随应用壳加载。
- 不得为了减少 import 行数，把页面样式重新汇总进 `styles.css`、`main.tsx` 或其他首屏静态依赖。
- 样式拆分以加载边界和领域归属为准，不要求每个页面机械地拥有一个 CSS 文件；共享领域 Chunk 可以被多个页面复用。

修改样式边界时，应同步维护 `src/web/page-styles.test.ts` 中的代表选择器和页面导入关系，防止页面规则重新进入首屏 CSS。

## 3. Bundle 预算

`config/bundle-budget.json` 是 Bundle 预算的唯一真实来源。预算分为四层：

| 预算 | 约束对象 | 目的 |
| --- | --- | --- |
| `entryJsGzipBytes` | JavaScript 入口 | 控制首屏脚本成本。 |
| `lazyChunkGzipBytes` | 单个懒加载 JavaScript Chunk | 防止单页脚本无限增长。 |
| `css.entryGzipBytes` | 首屏静态 CSS 依赖 | 保持应用壳轻量。 |
| `css.totalGzipBytes` | 全部 CSS Chunk 去重后的总量 | 控制全站样式规模。 |
| `css.routes` | 各动态页面相对首屏新增的 CSS | 按页面约束独立加载成本。 |

所有 `src/web/pages/` 动态入口必须在 `css.routes` 登记，键名必须与 Vite Manifest 的源码入口一致。缺少登记本身就是门禁失败，不能依赖全站总预算代替页面预算。

页面 CSS 预算按“该页面静态 CSS 依赖减去首屏 CSS 依赖”计算。共享领域 CSS 会计入每个使用它的页面预算，但在全站总量中只计一次。这种计算同时反映用户首次进入页面的真实增量和全站发布成本。

### 3.1 预算设置原则

- 新页面先完成真实内容和样式分包，再以生产构建的 gzip 结果设定预算。
- 预算应取略高于稳定测量值、便于审查的整数档位；保留小幅正常波动空间，但不得为未实现的未来功能预留大额容量。
- 页面接近预算时，优先删除重复规则、下沉组件样式或拆分加载边界，不得直接把样式移回入口 CSS。
- 调高任一预算必须在变更说明中给出增长来源、测量结果和无法继续拆分的理由。禁止仅为通过 CI 而整体放宽预算。
- 页面删除或重命名时必须同步删除或迁移预算项；预算指向不存在的 Manifest 入口同样属于错误。

## 4. PWA 预缓存

`scripts/build-pwa.mjs` 必须从 Vite Manifest 收集应用入口、全部动态页面及其静态依赖，不维护手写页面白名单。新增页面正常进入 Manifest 后，其 JavaScript、CSS 和共享依赖应自动进入 Service Worker 预缓存。

修改页面入口结构、Manifest 遍历或 CSS 加载边界时，必须同步验证：

- 至少存在一个动态页面入口，否则 PWA 构建应失败。
- 页面 JavaScript、页面 CSS 和递归静态依赖均写入 `sw.js`。
- 预缓存资源去重并保持稳定排序。
- 不把运行时 API、用户数据或带凭据 URL 纳入静态预缓存。

## 5. 测试与验证

涉及分包的变更至少应覆盖以下自动化检查：

- `src/web/page-styles.test.ts`：页面样式不在首屏 CSS，且由正确入口或组件加载。
- `scripts/check-bundle.test.ts`：首屏、总量、页面预算、缺失预算和异常 Manifest 的门禁行为。
- `scripts/build-pwa.test.ts`：全部动态页面及其 CSS、共享依赖进入预缓存。
- 现有主题测试：新增 CSS 继续遵循主题令牌和禁止硬编码颜色等约束。

最终必须在项目规定的 Node Docker 环境中执行 `npm run verify`。评审时应记录门禁输出中的首屏 CSS、CSS 总量和受影响页面的 gzip 实测值；只运行开发服务器不能证明生产分包正确。

## 6. 新增页面检查清单

1. 在 `src/web/app.tsx` 使用 `React.lazy()` 动态导入页面。
2. 将页面专属规则放入页面或领域 CSS，并从懒加载边界导入。
3. 在 `config/bundle-budget.json` 为页面登记独立 CSS gzip 预算。
4. 更新样式边界、Bundle 门禁和 PWA 预缓存相关测试。
5. 执行生产构建，确认 Vite Manifest 中存在动态页面及预期 CSS Chunk。
6. 执行 `npm run verify`，记录并审查首屏、总量和页面级预算结果。

## 7. 禁止做法

- 静态导入本可独立加载的页面，只为绕过页面预算登记。
- 把页面专属 CSS 放进全局入口，导致所有用户提前下载。
- 使用空页面、测试桩或临时删除样式得到虚假的低基线。
- 删除门禁测试、跳过生产构建或无理由扩大预算。
- 为 PWA 新页面维护手写资源列表，使 Manifest 与缓存范围脱节。

## 8. 接口配置与授权页拆分

接口配置页 `aigc-interfaces-page.tsx` 从 AIGC 工作台按需加载，专属表格、MCP 授权与抽屉样式位于 `aigc-interface-config.css`，不由工作台入口或应用入口静态导入。协议参数等既有逻辑与领域样式继续共享。

本次新增的客户端授权管理及配置抽屉需要独立样式，旧页面的 CSS 总量原本已接近 64 KiB。样式拆分后的首次实测为首屏 20096、原工作台 7141、接口配置页 9877、全站 68263 bytes gzip；后续交互修复会有小幅变化。全站预算由 65536 调整为 69632，接口配置页单独登记 10240，其他页面与首屏预算保持原值。增长来自新增页面专属样式，继续拆分不能降低全站去重后的总量。最终实测应以当前生产构建门禁输出为准。

## 9. 配置中心交互提示样式

未保存保护与生效提示使用按配置页加载的 `configuration-interactions.css`；语音编辑器专属布局拆至 `tts.css`，仅由语音页导入。AIGC 渠道页同时依赖既有工作台领域样式和新的配置提示，无法继续拆分其实际使用的提示样式；其预算从 6144 调整为 7168 bytes gzip，其他预算保持不变。生产构建实测首屏 CSS 20096、全站 CSS 69102、AIGC 渠道 6593、语音合成 4035、Provider 5209、Pi 运行设置 4370 bytes gzip。新增样式继续通过 Manifest 自动纳入 PWA 预缓存。

## 10. 语音配置列表与抽屉

语音配置列表、编辑抽屉与字段样式继续归属 `tts.css`，仅由懒加载的 `tts-page.tsx` 导入。抽屉键盘与确认逻辑不依赖 AIGC 页面专属样式。新增列表摘要、独立滚动抽屉和手机布局后，首次实测首屏 CSS 20096、全站 70025、语音页 4958 bytes gzip，相比上一轮全站与语音页均增加 923 bytes；首屏未增长。

语音页预算由 4096 调整为 5120，全站预算由 69632 调整为 70656，其余预算保持不变。新增样式均为语音页实际使用的布局与响应式规则，继续拆分只能改变加载边界，无法降低全站去重后的必要样式总量；禁止为此将规则移入应用入口。页面依赖仍由 Manifest 自动进入 PWA 预缓存，最终实测以构建门禁为准。

## 11. 渠道列表与共享配置弹层

AIGC 渠道页的列表、协议选择和字段样式归属 `aigc-channels.css`，由渠道页面懒加载；该页不再依赖整份 `aigc.css`。语音页与渠道页共享 `configuration-editor-dialog.tsx` 的键盘、焦点和滚动管理，共享抽屉样式由组件显式导入 `configuration-editor-dialog.css`；语音字段和列表继续归属 `tts.css`。所有新样式仍位于页面或组件加载边界，不进入应用壳。

生产构建实测首屏 CSS 20096、全站 70766、渠道页 5423、语音页 5269 bytes gzip。相对上一轮，全站增加 741，渠道页减少 1170，语音页增加 311。语音页增长来自将既有抽屉布局拆为独立共享 CSS 后的 gzip 分块开销；全站增长来自渠道列表、协议选择和响应式规则，已复用抽屉布局避免重复。继续拆分不能减少必要规则的总量，并会增加压缩边界开销；禁止把样式移到首屏绕过门禁。

全站预算由 70656 调整为 71680，语音页由 5120 调整为 5632；渠道页因移除不再使用的领域样式，将预算从 7168 收紧到 5632。首屏和其他页面预算保持不变。共享组件与两个页面资源继续由 Manifest 自动进入 PWA 预缓存，最终实测以生产构建门禁为准。

## 12. 图片灯箱共享样式

聊天附件、AIGC 产物查看及创作与运行的灯箱基础布局统一归属 `media-lightbox.css`，由 `MediaLightbox` 组件和两个 AIGC 懒加载页面显式导入。聊天缩放控件及关闭防误触样式继续归属 `chat.css`；产物缩略图和创作面板分别保留在 `aigc-assets.css`、`aigc.css`。直接进入 AIGC 页面无需先访问聊天页，灯箱样式不进入首屏，且通过 Manifest 自动进入 PWA 预缓存。

灯箱使用动态视口高度，扣除安全区、关闭按钮和操作栏后，以确定的网格画布双轴约束图片。手机单列创作预览也使用确定高度，避免图片固有尺寸撑大网格。加载边界由 `src/web/media-lightbox-styles.test.ts` 回归覆盖；共享样式独立压缩后，工作台首次实测为 7183 bytes gzip（原值 7141，原预算 7168）。新增动态视口与确定网格约束是该页实际使用的规则；继续拆分会增加压缩边界开销，不能移回首屏。工作台预算小幅调整为 7424，其余页面及首屏、全站预算保持不变，最终实测以全量验证输出为准。

## 13. Provider 摘要列表与分区管理抽屉

Provider 页面保持原有懒加载入口，摘要列表、搜索、模型目录、页签和手机布局归属 `providers.css`；新建、改名、删除和管理抽屉复用 `configuration-editor-dialog.tsx` 的焦点与滚动管理及组件 CSS，不进入应用壳。不为页面重组引入第三方依赖或修改预缓存收集逻辑。

首次生产构建实测首屏 CSS 20096、全站 71218、Provider 页 6410 bytes gzip。相对上一轮全站增加 452，Provider 页增加 1201：页面实际使用的摘要、页签与响应式规则增加 452，共享配置弹层 CSS 增加该页加载成本 749（该 CSS 已由语音和渠道页使用，不增加全站重复成本）。已移除旧窄栏和横向 Provider 列表规则；继续拆分无法减少必要样式的实际页面成本，不得移回首屏。

Provider 页预算从 5632 调整为 6656 bytes gzip，仅保留 246 bytes 正常波动空间；首屏、全站及其他页面预算不变。Provider 与共享弹层资源通过 Manifest 自动预缓存；最终测量以全量验证门禁输出为准。


## 14. 运行设置分区与声明来源

运行设置保持原有懒加载入口，作用域选择、三个设置页签、继承来源、已保存声明摘要及手机表单样式归属 `pi-settings.css`。版本冲突确认复用 `configuration-editor-dialog.tsx` 的焦点、键盘和忙碌保护；共享弹层 CSS 只随页面加载，不进入应用壳。不引入新依赖或修改 PWA 收集逻辑。

首次生产构建实测首屏 CSS 20096、全站 71996、运行设置页 5790 bytes gzip。相对上一轮全站增加 671，运行设置页增加 1420：新增页面必要样式增加 671，共享弹层 CSS 增加该页加载成本 749（全站已存在，不重复增加总量）。旧作用域布局与常驻 JSON 布局规则已替换，继续拆分不能降低实际页面依赖成本，禁止将规则移入首屏。

运行设置页预算从 4608 调整至 6144，全站从 71680 调整至 72704；首屏与其他页面预算不变。资源继续通过 Manifest 自动预缓存，最终实测以全量验证门禁输出为准。

## 15. Skills 与扩展分区及详情

资源配置页保留 `resources-page.tsx` 懒加载入口，三个分区、搜索、目录摘要、任务反馈和手机布局归属 `resource-catalog.css`，由该页显式导入；资源详情与安装/卸载确认复用配置弹层 CSS。工作区文件浏览器继续使用 `resources.css`，移除其中已不再使用的旧配置资源卡片、常驻内容和安装布局，保留文件浏览器及空态规则。不引入依赖或修改 PWA 收集逻辑。

生产构建首次实测首屏 CSS 20096、全站 72683、资源配置页 5822、工作区资源页 5660 bytes gzip。首屏保持不变；全站相比上一轮增加 687 bytes，增长来自必要的配置资源分区及任务状态样式，已移除旧规则避免重复。资源配置页独立样式和共享弹层无需加载整份文件浏览器 CSS，预算从 7168 收紧到 6144；全站和其他页面预算不变。继续通过 Manifest 自动预缓存，最终测量以全量验证输出为准。
