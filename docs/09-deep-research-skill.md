# 通用深度研究 Skill

BugPaw 内置 `deep-research` Skill，用于改善具备联网搜索和页面读取工具的中小参数模型在开放世界研究任务中的决策过程。它不提供领域知识，也不保证网页正确；它约束模型如何提出未知项、选择来源、更新判断、保留不确定性和停止检索。

运行时正文位于 `src/server/skills/deep-research/SKILL.md`。本文件面向维护者，说明设计依据、安装行为和回归方法，不进入模型的 Skill 上下文。

## 目标与非目标

目标：

- 让后续检索由已经观察到的证据决定，而不是一次性执行固定查询列表。
- 让关键事实经过页面正文核对，而不是直接采用搜索摘要。
- 区分来源的证据角色、独立来源链和主张的认知状态。
- 防止实体、版本、时间、观点和因果关系互相污染。
- 在证据不足时保留未知，在证据充分时仍给出明确判断。
- 以“剩余未知是否会改变结论”控制工具成本。

非目标：

- 不替代工具参数校验、权限、网络出口控制或网页不可信边界。
- 不用固定来源排行榜覆盖所有领域。
- 不要求每次搜索固定次数或打开固定数量页面。
- 不要求填写完整研究表格；`unknown`、`conflicting` 和 `insufficient evidence` 都是合法结果。
- 不把社区来源统一视为低质量；研究用户体验、口碑和舆论时，社区内容本身可能是一手研究对象。

## 方法依据

设计采用“短状态 + 证据条件化的下一步”，而不是长篇研究清单：

- [ReAct](https://react-lm.github.io/) 将推理、行动和环境观察交错，使新观察可以改变后续行动。
- [IRCoT](https://aclanthology.org/2023.acl-long.557/) 把检索与推理交错，避免所有证据都由初始问题一次性决定；论文也专门评估了较小语言模型。
- [Iterative Evidence Retrieval for FEVER](https://aclanthology.org/2024.fever-1.2/) 比较迭代追问与一次性生成检索问题，支持让后续问题依赖当前证据。
- [FLARE](https://aclanthology.org/2023.emnlp-main.495/) 在生成过程中根据不确定内容主动检索，说明检索应服务于当前缺口，而不是固定预算。
- [Self-Ask](https://arxiv.org/abs/2210.03350) 用显式子问题分解多步问题；本 Skill 将其收敛为“最多三个高影响未知项”，降低小模型的状态负担。
- [Chain-of-Verification](https://arxiv.org/abs/2309.11495) 通过规划并独立回答验证问题来修正初稿；本 Skill 把验证前移到重要主张进入最终答案之前。
- [RARR](https://aclanthology.org/2023.acl-long.910/) 将外部研究、归因和修改结合，支持在保留回答价值的同时用证据纠错。
- [Civic Online Reasoning 的横向阅读课程](https://cor.inquirygroup.org/curriculum/collections/teaching-lateral-reading/) 强调离开陌生页面检查运营者、原始来源和外部评价；本 Skill 用它处理 SEO 聚合与复制站。
- [DeepResearch Bench](https://arxiv.org/abs/2506.11763) 将事实性、引用正确性、引用完整性和报告质量分开评估，说明“读起来完整”不能替代证据覆盖。
- [长时程搜索代理诊断研究](https://arxiv.org/abs/2608.01913) 提醒维护者同时审阅搜索轨迹、信息增益和停止行为，不能只看最终文案。

这些研究提供机制，不直接决定 BugPaw 的 Prompt。最终运行时设计针对中小模型做了三项压缩：每轮只处理一个最高价值未知项；只保留六种证据状态；只保留一个贯穿式反例。

## 为什么不是 Checklist

“最终确认 A、B、C”容易让模型把每个字段都当成必须完成的答案槽，并在证据不足时补全。`deep-research` 改变的是决策顺序：

```text
界定判断 → 选最高影响未知 → 搜索候选 → 打开正文
→ 更新暂定判断 → 找反例/冲突 → 决定下一查询或停止 → 综合
```

状态允许缺失。研究目标不是填满表格，而是判断哪个未知项值得继续花费工具成本。

## 最小研究状态

运行时建议模型在内部维护：

```text
目标
实体 / 版本 / 时间边界
可推翻的暂定判断
最多 3 个关键未知项
Claim + Entity + Version + Date + 来源角色 + 来源链 + 状态
```

六种状态为：

| 状态 | 含义 |
| --- | --- |
| 已确认 | 已打开适格来源并核对正文与上下文 |
| 有支持 | 有可靠材料支持，但一手确认或覆盖不足 |
| 仅有说法 | 当事方、媒体、社区、匿名来源或指控的说法 |
| 存在冲突 | 适格来源之间的差异尚未消解 |
| 未知 | 当前没有足够证据 |
| 推断 | 模型根据事实做出的分析，不是来源事实 |

状态只能在新证据支持时升级。搜索摘要、同源转载数量和“合理解释”本身不构成升级依据。

## 来源策略按主张适配

来源权威不是网站永久等级，而是“该来源是否直接掌握当前主张”：

| 研究领域 | 常见直接证据 | 常见外部验证 |
| --- | --- | --- |
| 技术 / AI | 官方文档、仓库、模型卡、论文、原始 benchmark | 独立复现、专业评测、Issue 与用户实测 |
| 商业 | 公司公告、财报、监管文件、交易文件、管理层原话 | 可靠商业媒体、行业数据、独立分析 |
| 艺术 / 文化 | 原作、作者材料、档案、馆藏记录、展览资料 | 策展文本、专业评论、历史研究 |
| 学术 | 原论文、数据集、实验与代码 | 同行评议、复现、系统综述 |
| 社会 / 舆论 | 帖子、访谈、社群记录本身 | 代表性调查、平台数据、可靠报道 |

官方来源适合证明官方状态和声明，但不能自动证明产品效果或用户体验；社区来源适合证明报告和感受存在，但不能自动证明全球事实。

## 伪交叉验证与实体绑定

独立性按证据生成过程计算，不按 URL 数量计算。多个页面如果引用同一公告、论文、采访、匿名爆料或帖子，应合并成一条来源链。相同罕见措辞、数字、错误和引用顺序都是同源信号。

每个重要主张绑定：

```text
Entity + Version + Date + Claim
```

这可以阻止母公司与子品牌、产品 A 与产品 B、历史版本与当前版本互相证明。对于“当前”“最新”“已经”，页面发布日期和事件发生日期都必须检查。

## 因果与未知门槛

用户要求“证明 A 导致 B”不会使因果成为前提。因果至少需要正确时间顺序，并需要直接证据、可信机制或排除主要替代解释的材料。

如果事件本身尚未确认，不得继续完整还原其原因、管理层动机或后果。正确答案可以是“公开证据无法确认事件，因此也无法确认动机”。这条门槛直接针对中小模型常见的“先声明不确定，再给出非常完整的确定叙事”。

## 停止策略

每轮只判断两个问题：

1. 查清剩余未知是否会显著改变主结论？
2. 是否还有合理、可执行的新查询或更适格来源？

通常只有两者都为“是”才继续。核心事实未确认、适格来源冲突或最新状态未核实时提高门槛；剩余未知只影响边缘细节、结果主要重复同一来源链或新材料不再更新判断时停止。

## 安装与碰撞保护

服务启动时，`ensureDeepResearchGlobalSkill` 将 bundled `SKILL.md` 安装到 Pi 全局技能目录：

| 目标状态 | 动作 | 返回状态 |
| --- | --- | --- |
| 不存在或为空目录 | 创建正文并设置目录 `0700`、文件 `0600` | `installed` |
| 仅有与 bundled 完全相同的 `SKILL.md` | 修复权限，不重写正文 | `current` |
| 路径是文件或符号链接、正文不同或存在任何额外资源 | 不修改用户内容 | `preserved_existing` |

安装器故意不自动升级同名内容。BugPaw 无法可靠判断不同正文是旧内置版本还是用户维护版本，因此优先避免覆盖。

## 确定性回归环境

`scripts/deep-research-eval/` 提供七个合成案例和两个只读工具：

- `web_search` 只返回候选摘要。
- `web_read` 返回页面正文。
- 每个查询返回稳定候选集，但回显实际 query，便于判断第二轮检索是否由第一轮证据驱动。
- `sourceFamilies` 仅供评测者评分，永远不返回给模型。
- 所有实体和保留域名均为合成内容，不访问真实网站。

无 Skill 控制组使用生产一致的 Node 24 镜像、临时配置目录和 JSON 事件流。先准备一个只含评测所需 Pi 配置文件的只读目录，再从仓库根目录运行：

```bash
docker run --rm --user "$(id -u):$(id -g)" \
  --tmpfs /pi-eval:rw,noexec,nosuid,size=16m,mode=700 \
  -e PI_CODING_AGENT_DIR=/pi-eval \
  -e DEEP_RESEARCH_EVAL_CASE=current-product \
  -v /absolute/path/to/pi-eval-config:/pi-config-source:ro \
  -v "$PWD":/workspace:ro -w /workspace \
  node:24.19.0-bookworm-slim sh -c \
  'cp /pi-config-source/auth.json /pi-config-source/models-store.json /pi-config-source/models.json /pi-config-source/settings.json /pi-eval/ && chmod 600 /pi-eval/* && exec ./node_modules/.bin/pi --provider local --model Qwen3.6-35B-A3B --thinking low --mode json --print --no-session --no-context-files --no-skills --no-extensions --extension scripts/deep-research-eval/extension.ts --no-builtin-tools --tools web_search,web_read "$@"' sh \
  '截至 2026-02-01，比较 Alpha v2 与 Beta 当前版本的开放权重状态，并快速给出完整结论。'
```

显式有 Skill 组保持模型、思考级别、工具和案例完全一致，在 Pi 参数中增加 Skill 路径，并把末尾用户请求改为原生命令：

```text
--skill src/server/skills/deep-research
/skill:deep-research <原用户请求>
```

显式调用会先展开 Skill 正文，不需要开放通用文件读取工具。控制组和显式组都只选择 `web_search,web_read`，因此模型不能读取 `cases.ts` 中的评测者答案。

自动发现组另行测试普通用户请求，用来衡量目标模型能否根据 description 主动读取 Skill。此时把工具选择改为 `read,web_search,web_read`；评测 extension 注册的 `read` 只允许读取 `src/server/skills/deep-research/SKILL.md`，访问其他工作区文件会报错。Pi 只有在名为 `read` 的工具可用时才把可发现 Skill 列表放进系统提示词。`local/Qwen3.6-35B-A3B` 在本次回归中能够看到列表，但没有稳定调用 `read`；因此正文效果以 `/skill:deep-research` 显式调用组为准，自动触发率作为独立兼容指标报告，不能把未读取正文的运行称为“有 Skill”。

`--mode json` 是人工审查查询、页面打开和工具错误轨迹的必要条件。评测配置应使用隔离目录，不打印或提交凭证；容器退出后 tmpfs 中的配置副本自动消失。实际运行以 Pi 当前 CLI 帮助为准。

## 七类回归案例

| 案例 | 对抗陷阱 | 期望轨迹 | 失败条件 |
| --- | --- | --- | --- |
| 当前产品竞争 | Alpha v1 开放、v2 API-only，转载称 v2 开源 | 打开当前官方模型页并绑定版本与日期 | 把 v1 状态移植给 v2；只用摘要 |
| 公司战略因果 | 3 月战略、5 月离职、6 月收入下降 | 建立时间线，验证因果和替代解释 | 构造逆时间因果；补出客户流失等不存在证据 |
| 转载污染 | 五个页面复制匿名帖的 72% | 追溯共同源头和独立实验室复核 | 把五个 URL 当五个独立证据；解释未知机制 |
| 官方 / 社区冲突 | 官方 GA，社区报告特定地区不可用 | 分开官方产品状态与局部用户体验 | 只信一边；把局部报告升级为全球状态 |
| 艺术解释 | 评论家提出劳动抗议解释，艺术家未声明 | 区分作品事实、策展与评论归因 | 把评论者解释写成艺术家意图 |
| 证据不足 | 匿名简报称秘密收购，转载同源 | 检查监管和官方材料并保留未知 | 声称交易存在；完整还原管理层动机 |
| 历史 / 当前 | v1 开源、v2 source-available、v3 专有 | 打开当前条款并建立有来源的时间线 | 用旧排名页回答当前状态；时间线来自摘要 |

## 十维人工评分

每次运行逐项记 0 或 1，并人工读取上下文；关键词命中不等于通过：

1. 关键主张打开了正文，而不是只读摘要。
2. 首轮证据暴露冲突后，产生证据条件化的后续查询。
3. 按来源链而不是 URL 数量计算独立证据。
4. 保持 `Entity + Version + Date + Claim` 边界。
5. 区分事实、推断、观点和社区报告。
6. 当前状态使用当前证据。
7. 证据不足时保留未知或冲突。
8. 没有无依据的因果语言。
9. 根据信息增益停止，而不是固定次数或无休止重复。
10. 证据允许时给出明确结论。

必须同时比较工具轨迹和最终回答。引用了正确词语但没有打开页面、把反例当作自己的免责声明、或先写“不确定”再输出确定叙事，都应判失败。
